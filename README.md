# filepawl

A file-length ratchet and directory-count gate, extracted from three consumer repositories (HQPTuner, Gauntlet, Trivia Judge) into one installable package.
filepawl enforces caps on file length and files per directory, with a one-way ratchet (allowance) on files above a watch line to stop them growing past reasonable size.

## Install

Install from GitHub:

```bash
pip install git+https://github.com/ohshitgorillas/filepawl.git@vX.Y.Z
```

Replace `vX.Y.Z` with a tag.
For the `mv` command (file moves with import rewriting), install the optional `mv` extra, which adds `rope`:

```bash
pip install git+https://github.com/ohshitgorillas/filepawl.git@vX.Y.Z#egg=filepawl[mv]
```

Requires Python 3.12 or later.

## Policy

Configuration lives in `pyproject.toml` under `[tool.filepawl]`.
Every key is optional; defaults are shown below.

```toml
[tool.filepawl]
languages = ["python"]
tests = ["tests/**"]

[tool.filepawl.length]
cap = 500
cap_tests = 800
watch = 400

[tool.filepawl.dircount]
cap = 15
cap_tests = 30
exclude = ["__init__.py"]

[tool.filepawl.exempt]
# path = reason. Human-edited. Exempts from the hard cap only; the file still
# needs an allowance entry and may not grow.
# "scripts/junkcal_fixture.py" = "junkcal fixture oracle, provenance kept whole"

[tool.filepawl.python]
include = ["**/*.py"]
mover = "rope"

[tool.filepawl.javascript]
include = ["**/*.js", "**/*.css"]
mover = "command"
mover_command = "npx jscodeshift -t scripts/move.js --old {old} --new {new} src/"
```

A language block specifies which files it covers (via `include` globs), which mover to use (defaulting to `git mv`), and for `command` movers, the command template.
The `tests` globs match test file patterns; files matching these patterns use `cap_tests` instead of `cap` and have no ratchet.

Exempt entries are human-edited in the `[tool.filepawl.exempt]` table and name files that are allowed to exceed the hard cap (for unavoidable cases like fixture oracles or generated data).
An exempt file still needs an allowance entry and may not grow past it.

## State

filepawl owns `.filepawl.toml`, committed to the repository, containing the ratchet state.
Do not edit it by hand; use `filepawl accept` instead.

```toml
# Generated by filepawl. Do not edit; run `filepawl accept`.
version = 1

[allowance]
"hqptuner/conf/matrixconf.py" = { lines = 496 }
"triviajudge/core.py" = { lines = 444, reason = "Line record plus its readers" }
```

The `lines` field is the allowed length for that file.
The optional `reason` field documents why the file needed an allowance and is preserved when `accept` lowers the entry.

## Commands

Run `filepawl check [PATH...]` to report findings over the tree.
Findings are one per line: `path: message`.
If the check reports any findings, the last line prints the exact `filepawl accept` command to fix them (when they are fixable).

- Exit 0: clean, no findings.
- Exit 1: findings reported (use `filepawl accept` to fix most of them).
- Exit 2: configuration error (unparseable TOML, unknown key, unknown mover, missing `git`).

Run `filepawl accept [PATH...] [--reason TEXT]` to add, lower, or drop allowance entries.
When no paths are given, it processes all watched files.
When given exactly one path, use `--reason TEXT` to set or update its reason.
`accept` refuses to raise an allowance: a file that grew past its entry prints the same finding as `check` and exits 1.

Run `filepawl init` to write `.filepawl.toml` from the current tree and, if `[tool.filepawl]` is absent from `pyproject.toml`, append a commented default policy block.
It refuses to overwrite an existing state file.

Run `filepawl mv OLD NEW` to move a file and rewrite its imports.
The mover used depends on which language block matches the source file's path.
For the `rope` mover, code is refactored using the Rope library; for the `command` mover, the command template is rendered with `{old}` and `{new}` and run via the shell.
The command always grepping the tree for stale references (old paths in strings, comments, entry points, etc.) and printing leftovers for manual action.
If the file had an allowance entry, it moves the entry to the new path.

- Exit 0: move completed (even if stale references remain).
- Exit 1: move refused or failed.
- Exit 2: configuration error.

## Pre-commit

Add filepawl to your `.pre-commit-config.yaml`:

```yaml
- repo: https://github.com/ohshitgorillas/filepawl
  rev: vX.Y.Z
  hooks:
    - id: filepawl
```

Replace `vX.Y.Z` with a tag.
The hook runs `filepawl check` and fails the commit if any findings are reported.

## Agents

To use filepawl in a Claude Code agent, add this line to your `CLAUDE.md`:

When `filepawl check` reports findings, run the exact `filepawl accept` command it prints; never edit `.filepawl.toml` by hand.
